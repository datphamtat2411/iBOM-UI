# Homepage Creative Resources

You are free to search and use any other high-quality sources available to you beyond the resources listed here. Treat this document as a curated starting point, not a whitelist or a restriction.

## Purpose

Use these resources when exploring, prototyping, and redesigning the iBOM homepage.

The goal is not to copy any reference literally. Study strong work for:
- composition
- typography
- motion language
- interaction patterns
- pacing
- depth
- transitions
- WebGL techniques
- creative coding approaches
- visual storytelling

Then create an original implementation appropriate for iBOM and its product story.

## Asset Usage Rules

- Search broadly. The sources above are recommendations, not limits.
- Prefer CC0, public-domain, MIT, ISC, Apache-2.0, or similarly permissive assets when possible.
- Commercial-use assets are acceptable when their license clearly permits the intended use.
- Do not copy proprietary visual assets from reference websites.
- Do not rip assets from games, films, paid products, or websites that do not grant reuse rights.
- Do not assume an asset is free just because it is downloadable.
- Verify the license of the actual asset being used.
- Record attribution or license notes when required.
- Download production assets into the repository instead of hotlinking remote files whenever practical.
- Optimize assets for the web when practical.
- Do not collect assets speculatively. Add them when they support an actual homepage implementation.
- External assets should support the creative direction rather than determine it.

## Creative Development Principles

The homepage is allowed to be code-first.

No Figma, Blender, pre-rendered motion design, or manually designed 3D asset pipeline is required by default.

Creative work may be produced directly with:
- HTML / CSS / SVG
- GSAP
- Three.js
- WebGL
- GLSL shaders
- Canvas
- procedural geometry
- particles
- instancing
- lines and curves
- image planes
- video textures
- typography
- DOM + WebGL composition
- scroll-driven timelines
- pointer interaction
- browser-ready external assets

During foundation tasks, prioritize technical capability and reliability over appearance.

During final redesign tasks, use the existing foundation aggressively and allow the visual direction to evolve. Avoid defaulting to the safest implementation merely because it is conventional.

## Reference Discipline

A reference is input, not a specification.

When studying another website:
1. Identify what makes the experience effective.
2. Extract reusable principles or techniques.
3. Reinterpret them for the iBOM product story.
4. Build an original result.

Do not recreate another site's branding, proprietary artwork, copy, or distinctive assets.

## Homepage Product Story

When choosing visuals or interactions, keep the core iBOM narrative in mind:

**One source profile → structured transformation → multiple specialized CV/profile versions.**

Creative decisions do not need to depict this literally, but the final homepage should still communicate the product rather than becoming an unrelated visual demo.
